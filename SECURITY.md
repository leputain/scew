# Security policy

## Сообщить об уязвимости

Не создавайте публичный issue, если сообщение содержит токены, Telegram ID,
персональные данные, внутренние адреса или детали production-инфраструктуры.
Используйте GitHub Private Vulnerability Reporting владельца репозитория.

В сообщении укажите затронутую версию, сценарий воспроизведения, ожидаемое
влияние и безопасный способ проверки. Не прикладывайте production `.env`, дампы
базы, полные логи или Telegram export.

## Поддерживаемая версия

Security fixes применяются к текущей версии из `VERSION`. Более старые Docker
images предназначены только для краткосрочного rollback.

## Правила обращения с секретами

- секреты хранятся только в `.env` или внешнем secret manager;
- реальные токены и chat/user IDs не добавляются в примеры и тесты;
- дампы, логи, сертификаты и export-файлы не коммитятся;
- при подозрении на утечку сначала отзовите секрет, затем очищайте историю Git;
- перед push запускайте `python scripts/public_repo_audit.py`.
